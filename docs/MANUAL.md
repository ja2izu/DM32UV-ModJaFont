# DM32UV-ModJaFont 取扱説明書（Ver 0.99）

DM-32UV のフォントを日本語化する手順です。無線機は **通常の状態（電源を入れた状態）** のまま、CPS と同じ通信方式で扱います。特別な起動操作や、マイクロコードの転送は使いません。

## 0. はじめに（必ずお読みください）

- 無線機のフラッシュを書き換えます。**自己責任**でお使いください。無保証です。
- **初めて書き換える前に、フルダンプを取ってください**（→ 7章）。このリポジトリに純正のフォントは含まれません。元に戻す手段は、利用者自身のバックアップだけです。
- 作者の無線機で確認した手順です。ファームウェアの版・個体による違いは未確認です。
- 書き込めるのは、フォント3領域だけです。校正データ・連絡先・設定には触れません。

## 1. 用意するもの

| | |
|---|---|
| パソコン | Windows など。Python 3 と `pyserial`（`pip install pyserial`） |
| 無線機 | Baofeng DM-32UV |
| ケーブル | プログラミングケーブル（USB-シリアル変換チップは CH340、FTDI のどちらでも動作を確認） |
| このリポジトリ | `tools/` の2つのスクリプトと、`patch/DM32UV_ModJaFont_v2.patch` |

保存ファイルが無線機ごとに混ざらないよう、無線機ごとに作業フォルダを分けることをお勧めします。以降のコマンドは、作業フォルダで実行する前提です。ツールとパッチのパスは、置いた場所に読み替えてください。

## 2. 準備

1. 無線機の **電源を入れ**、ケーブルでパソコンにつなぎます。
2. ポート名（例: `COM7`）を調べます。ケーブルを抜いてデバイスマネージャーの「ポート」を見てから挿し、増えたものが該当です。
3. CPS や、ポートを使う他のソフトは閉じます。

以降の `COM7` は、自分のポート名に読み替えてください。`--adapter CH340` のように付けると、使ったケーブルのチップ名がログに記録されます（付けなくても動作します）。

## 3. 通信の確認（`info`）

```
python3 tools/dm32_fonttool.py info --port COM7 --adapter CH340
```

無線機が応答するかの確認です。何も書き換えません。

## 4. 読み出す（`read`）

```
python3 tools/dm32_fonttool.py read --port COM7 --region all --out readback --adapter CH340
```

- 3領域（`Radio_Y16`、`HZK24S`、`HZK24T`）が `readback` に保存されます（例: `Radio_Y16_read_0.bin`）。
- 既存のファイルは上書きしません（末尾の枝番が増えます）。
- 所要時間の目安（CH340）: 約2分

## 5. パッチを重ねる（`apply`）

```
python3 tools/dm32_fontpatch.py apply --patch patch/DM32UV_ModJaFont_v2.patch --out-dir patched --item Radio_Y16=readback/Radio_Y16_read_0.bin --item HZK24S=readback/HZK24S_read_0.bin --item HZK24T=readback/HZK24T_read_0.bin
```

- `patched` に `Radio_Y16_patched.bin`（524,288 B）、`HZK24S_patched.bin`（498,528 B）、`HZK24T_patched.bin`（77,824 B）ができます。
- HZK24T は、読み出したファイル（101,520 B）の先頭 77,824 B だけを使います。後ろは連絡先データなので、書き込みません。
- 読み出し直後のファイル名の枝番は、環境に合わせて読み替えてください。

パッチの内容は `python3 tools/dm32_fontpatch.py info --patch patch/DM32UV_ModJaFont_v2.patch` で見られます。SHA-256 は `SHA256SUMS` と照合できます。

## 6. 書き込む（`write`）

先に、計画だけを表示して確認できます（ポートは開きません）。

```
python3 tools/dm32_fonttool.py write --dry-run --item Radio_Y16=patched/Radio_Y16_patched.bin --item HZK24S=patched/HZK24S_patched.bin --item HZK24T=patched/HZK24T_patched.bin
```

書き込み:

```
python3 tools/dm32_fonttool.py write --port COM7 --adapter CH340 --backup-dir backup --item Radio_Y16=patched/Radio_Y16_patched.bin --item HZK24S=patched/HZK24S_patched.bin --item HZK24T=patched/HZK24T_patched.bin
```

- 書き込み計画が表示され、`WRITE` と入力すると始まります。確認は無線機に接続する **前** に行います。
- 書き込む前に、今のフォントを `backup` に自動で保存します（`backup_Radio_Y16_0.bin` など）。
- 書き込んだあと、全ブロックを読み直して照合します。最後に **「照合結果: 一致」** と出れば成功です。
- 領域を1つだけ指定することもできます（例: `--item HZK24T=patched/HZK24T_patched.bin`）。
- 終わったら、無線機の電源を入れ直してください。
- 所要時間の目安（CH340）: Radio_Y16 + HZK24S で約5分30秒、HZK24T のみで約26秒。**終わるまで、ケーブルを抜いたり電源を切ったりしないでください。**

### 元に戻す

自動バックアップ（`backup_*.bin`）を、そのまま書き戻せます。

```
python3 tools/dm32_fonttool.py write --port COM7 --adapter CH340 --backup-dir backup2 --item Radio_Y16=backup/backup_Radio_Y16_0.bin --item HZK24S=backup/backup_HZK24S_0.bin --item HZK24T=backup/backup_HZK24T_0.bin
```

## 7. フルダンプとリストア

フラッシュ全体の保存（フルダンプ）と書き戻し（リストア）は、このツールにはありません。**OpenUV008** などを使ってください（入手は「OpenUV008」で検索）。使い方は、そのツールの説明に従ってください。動作がおかしくなったときは、フルダンプからのリストアで復旧できます。

## 8. 校正データの保存（`calread`）

校正データは、無線機ごとに値が違います。保険として、保存しておくことをお勧めします。

```
python3 tools/dm32_fonttool.py calread --port COM7 --adapter CH340
```

校正データのブロックを探して読み出し、`DM32_CD_xxxxxxxx_0.bin` のような名前で保存します。何も書き換えません。**その無線機のものと分かるように保管し、他人に渡さないでください。** このツールに、校正データの書き戻し機能はありません。復旧はフルダンプのリストアで行ってください。

## 9. 日本語名を書き込む

名前の書き込みは **[NeonPlugJA](https://github.com/ja2izu/NeonPlugJA)** で行います。ブラウザを日本語表示にして無線機に接続すると、フォントを自動で判定し、日本語名を有効にします。機種名の横に **ModJaFont** と表示されれば、判定できています。

漢字が表示されないときは、無線機に古いコードプラグが入っていることがあります。最新のコードプラグを書き込んでから、もう一度確認してください。

## 10. うまくいかないとき

- **ポートを開けません**: 他のソフトがポートを使っています。CPS などを閉じてください。
- **応答がない・途中で止まる**: 電源が入っているか、ポート名が合っているか（`info` で確認）を見てください。USB ハブを経由せず直接挿す、短いケーブルや別のケーブルを試す、も有効です。
- **書き込みが拒否される（`90 fe 98 fe`）**: 無線機が書き込みを受け付けなかったときの応答です（これまでの観察では、接続したまま長く待ったときに出ました）。電源を入れ直して、もう一度実行してください。
- **「照合不一致」**: 書き込んだ内容が正しく入っていません。そのまま使わないでください。同じコマンドをもう一度実行するか、バックアップを書き戻してください。
- **書き込みの途中で止まった**: 領域が中途半端な状態の可能性があります。電源を入れ直し、同じファイルで `write` をやり直してください。

## 11. 安全のための仕組み

- 保存ファイルは、必ず枝番つきの新しい名前で保存します（上書きしません）。
- 書き込める範囲は、フォント3領域だけです。決められたサイズ以外のファイルは書き込みません。
- 書き込む前に、今の内容を自動で保存します。保存に失敗したら書きません。
- 書き込んだあと、全ブロックを読み直して照合します。
- 確認の入力（`WRITE`）は、無線機に接続する前に行います。

## 12. 不具合を報告するとき

実行したコマンドと、画面に出た内容（最初から最後まで）をそのまま貼ってください。ログ `dm32_fonttool.log` も参考になります。**校正データのファイルや、無線機のシリアル番号などは、貼らないでください。**
